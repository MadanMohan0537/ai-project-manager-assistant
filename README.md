# AI Project Manager Assistant

A Cloudflare-native project-management workspace that turns a project brief and team profile into an actionable delivery plan, then lets you track execution through WBS, board, timeline, workload, RAID and AI-copilot views.

## Live Demo

**Deployment:** https://ai-project-manager-assistant.madanmohanlearning.workers.dev/

[Open AI Project Manager Assistant](https://ai-project-manager-assistant.madanmohanlearning.workers.dev/)

## What changed in v3

The original project was a single-form AI plan generator. v3 rebuilds it as an actual project workspace:

- Portfolio dashboard with project and delivery metrics
- Structured WBS grouped into project epics
- Task status tracking across Backlog, To do, In progress, Review and Done
- Kanban-style board
- Dependency-aware timeline generated by deterministic scheduling code
- Milestones derived from epic completion dates
- Team workload and capacity view
- Full RAID register: Risks, Assumptions, Issues and Dependencies
- Executive project status report
- JSON project export
- Browser-local project persistence
- Dedicated project-aware AI copilot endpoint
- Richer project intake: objective, requirements, methodology, dates, stack, constraints and team profiles

## Architecture

```text
Browser workspace
   |
   |-- Project state + task status -> localStorage
   |
   |-- POST /api/projects/plan
   |          |
   |          +--> Cloudflare Workers AI
   |          |      proposes WBS, assignments and RAID
   |          |
   |          +--> Worker scheduling layer
   |                 validates IDs/dependencies
   |                 calculates start/end days
   |                 derives milestones/workload
   |
   +-- POST /api/copilot
              |
              +--> Workers AI with current project context
```

The AI is intentionally not trusted to calculate the final schedule by itself. It proposes tasks and backward-only dependency references, while TypeScript normalizes task IDs, removes invalid dependencies, computes dates and derives milestone/workload metadata.

## Planning flow

1. Create a project and provide objective, description, dates, methodology, stack and constraints.
2. Add team members with role, skills and available capacity.
3. Workers AI produces a structured WBS, assignments, RAID register and delivery insights.
4. The Worker validates and schedules the task graph.
5. The browser saves the generated workspace locally.
6. Use Tasks, Board, Timeline, Team, RAID and Reports views during execution.
7. Ask the AI Copilot project-specific questions about blockers, risk, workload and next actions.

## API

### `GET /api/health`

Returns service/runtime health information.

### `POST /api/projects/plan`

Example request:

```json
{
  "name": "Customer Analytics Platform",
  "objective": "Launch a usable analytics platform for support leaders.",
  "description": "Build ingestion, authentication, dashboards, filtering and reporting.",
  "startDate": "2026-08-20",
  "targetDate": "2026-09-20",
  "methodology": "Agile",
  "stack": "TypeScript, Cloudflare Workers, D1",
  "constraints": "Small team and fixed beta date.",
  "team": [
    {
      "name": "Alice",
      "role": "Frontend Engineer",
      "skills": "React, TypeScript, design systems",
      "capacity": 100
    }
  ]
}
```

`POST /api/run` is retained as a backwards-compatible alias.

### `POST /api/copilot`

```json
{
  "question": "What is most likely to delay this project?",
  "project": { "...": "current project state" }
}
```

## Data persistence

Project workspaces are currently saved in browser `localStorage`. This keeps deployment zero-configuration and prevents a database binding from breaking the existing Workers deployment. It also means project data is device/browser-specific and is not yet synchronized between users or devices.

For production multi-user use, the next persistence layer should be Cloudflare D1 with authentication and server-side project ownership.

## Current limitations

- Persistence is browser-local, not account-based.
- Board cards change status through a selector rather than drag-and-drop.
- Timeline is a dependency-aware delivery timeline, not a full critical-path/PERT engine.
- Copilot recommends project changes but does not autonomously mutate project data.

These limitations are documented intentionally so the repository description matches the product that is actually implemented.
